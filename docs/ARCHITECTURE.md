# Architecture

## 设计目标

GraphMind Agent 将“知识获取”和“问题回答”拆分为两个阶段，使回答能够追溯到图谱中的实体、关系和来源文档。代码不绑定具体行业、地区或研究对象。

## 构建阶段

1. `ingest.py` 发现并读取文本/Markdown/HTML，清理 HTML 标签与多余空白。
2. `extractor.py` 使用领域中立的提示词，请模型输出结构化实体和关系。
3. `graph.py` 以规范化名称生成稳定标识，合并重复项并过滤端点缺失的关系。
4. `cli.py extract` 将结果保存为可审查的 `graph_bundle.json`。
5. `cli.py import` 通过参数化 Cypher 将实体、关系和来源引用写入 Neo4j。

## 问答阶段

1. `qa.py` 从问题中提取少量检索词。
2. `graph.py` 在实体名称、描述和关系类型中执行大小写不敏感的匹配。
3. 召回结果被转换为 `起点 -[关系]-> 终点` 证据三元组。
4. 模型只能根据给定证据组织答案；证据为空时不调用生成回答。
5. `Answer` 同时返回自然语言回答和结构化证据，便于审计。

## 数据模型

- `SourceDocument`：文档 ID、标题、相对来源引用
- `Entity`：实体 ID、名称、类型、描述、属性、来源文档
- `Relation`：关系 ID、起点、类型、终点、描述、来源文档
- `GraphBundle`：可导入的完整图谱包
- `Evidence` / `Answer`：检索证据和最终回答

## 安全边界

- 配置只从环境变量读取，源码无凭据默认值。
- 文档来源只保存相对路径，避免暴露开发机目录。
- Cypher 使用参数传值；动态关系类型先被规范化为受限字符集合。
- 模型输出先做 JSON 提取和 Pydantic 校验，再进入图谱。
- 数据集和运行产物不属于代码仓库内容。

## 可扩展点

- 在 `ingest.py` 增加 PDF/Office 解析器。
- 在 `extractor.py` 注入可配置本体或实体类型约束。
- 将 `retrieve()` 替换为全文索引、向量检索或混合检索。
- 在 `qa.py` 增加多轮状态、工具路由或回答评估。

以上均为扩展接口说明，不代表当前版本已经实现。
